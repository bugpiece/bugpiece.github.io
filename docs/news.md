# News の追加方法

短い記事を `news/<slug>/index.md` に置くと、News 一覧に新しい順で表示されます。
個別 URL は `/news/<slug>/`。タイトルや日付を変えても URL は変わりません。
公開後はフォルダ名を変えないでください。`permalink` の指定は不要です。

## 1. 記事を作成

`docs/news-template.md` を `news/chi-2026/index.md` などへコピーし、
タイトル・日付・本文を編集します。本文は数文程度の Markdown を想定しています。
写真なしでも投稿できます。下書きは front matter に `published: false` を追加します。
公開時にその行を削除してください。
`published: false` は本文だけを非公開にします。写真は静的ファイルとして公開されるため、
未公開にしたい写真は公開リポジトリへ追加しないでください。

## 2. 写真を追加

記事と同じ `news/<slug>/` に元画像を置くだけで準備できます。
HEIC・HEIF・JPEG・PNG・WebPに対応し、拡張子の大文字小文字は問いません。
`1.HEIC`, `2.jpg`, `3.png` のように番号を付ければ、その順番で登録されます。

```text
news/
  2026-08-24_lab-join/
    index.md
    1.HEIC
    2.jpg
    3.png
```

リポジトリのルートで、いつものビルドまたはプレビューを実行します。

```sh
sh scripts/jekyll.sh build
# または
sh scripts/jekyll.sh serve --livereload
```

初回は専用Python環境を自動作成します。Python 3.11以降を使用してください。
ビルド前に `photo-01.webp` などを生成し、記事の `photos` に自動登録します。
元画像は、WebPの生成・読み込み確認・記事更新がすべて成功した後に削除します。
元画像の保管用コピーは作りません。変換に失敗した入力は残します。
GitHubへ送るのは記事と生成済みWebPです。

本文はそのまま保持され、既存写真への追記にも対応します。
画像だけのフォルダーには `published: false` の記事ひな形を作成します。
タイトル・本文と `alt`（写真の説明）を編集し、公開するときに `published: false` を削除してください。
公開済み記事に写真を追加した場合はその公開状態を維持します。
プレビュー起動後に元画像を追加したときは、コマンドを再実行してください。
直接 `bundle exec jekyll` を実行すると画像の前処理は行われません。

```yaml
photos:
  - file: photo-01.webp
    alt: "Presenting our demo at the conference"
    width: 1200
    height: 800
    caption: "Photo by ..."
```

一覧には先頭の1枚だけを16:9に切り抜いて表示し、写真やタイトルから個別記事へ移動します。
PC・スマートフォンとも写真の横幅を本文幅に揃えます。画像の引き伸ばしや余白はありません。
16:9より横長の写真は左右、それより縦長の写真（3:2・正方形・縦写真など）は上下が切れます。
既定では中央を残します。先頭写真に `focus: top` / `bottom` / `left` / `right` / `center` を
指定すると、残したい位置を選べます。例えば顔が上部にある縦写真なら `focus: top` が適しています。
ただし9:16の縦写真では高さの約32%しか表紙に入りません。全体に情報があるポスターや集合写真は、
別の写真を先頭に置き、切り抜きに向いた表紙を選ぶことを推奨します。
一覧には本文の最初の段落を抜粋します。表示量は画面幅に応じて変わり、PCでは最大3行、
スマートフォン（幅640px以下）では最大4行とし、収まらない部分は `…` で省略します。
個別記事では写真を1枚ずつ大きく表示し、画像の左右の矢印ボタンと写真下の丸いインジケーターで切り替えます。
写真は元の縦横比で全体を表示します。高さは画面の70%以内に収め、縦写真が長くなりすぎるのを防ぎます。
一覧の写真は遅延読み込みします。個別記事の写真から画像単体を開けます。
JavaScriptが無効の場合は、全写真を縦に並べて表示します。

変換は長辺最大1200px、WebP品質85です。縦横比を維持し、拡大・切り抜きは行いません。
容量を理由にさらに解像度を下げる処理はありません。
写真の向きを補正し、EXIF・XMP（GPSなど）を出力に引き継ぎません。
ICCカラープロファイルがある場合は維持します。
記事に登録済みのWebPは再変換しないため、再ビルドで重複・再圧縮は起きません。
動く画像には対応していません。HEICは主画像を使用します。

変換後の構成：

```text
news/
  chi-2026/
    index.md
    photo-01.webp
    photo-02.webp
```

記事と画像が同じフォルダなので対応が明確です。画像は名前だけで指定できます。
この News については、既存の `images/` 一括管理の例外とします。
別アプリや追加のJavaScriptビルドは不要で、変換は投稿前のローカル操作です。

## 3. 確認

`sh scripts/jekyll.sh serve --livereload` で `/news/` と個別記事を確認します。
`sh scripts/jekyll.sh build` で本番用ビルドを確認します。
`docs/`・`scripts/`・`local/` は公開されません。
GitHub Actionsでもビルド前に同じ変換処理を実行します。
